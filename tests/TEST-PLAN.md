# Playable Novel · 测试清单（原子级用例 + 验证点）

> 目标：把「测什么、怎么验」固化成可执行的清单。每条用例都可以被翻译成一个断言；
> 验证点写的是**可观测的具体值**（DOM 选择器、state 字段、网络请求、存储键），
> 不是「看起来正常」这类无法判定的描述。
>
> 编号规则：`<模块>-<序号>`，模块前缀见下方索引。
> 状态列：**A** = 已有自动化；**M** = 需人工执行；**—** = 尚未自动化（待补）。

---

## 0. 测试分层与运行方式

| 层 | 职责 | 载体 | 运行命令 |
|---|---|---|---|
| L1 单元 | 纯函数/解析器，不依赖 DOM | `tests/parsers.test.js` | `NODE_PATH=<ws>/node_modules node tests/parsers.test.js` |
| L2 契约 | 云服务 SDK 封装（cloud.js）与后端 API | `tests/cloud.test.js`（待建） | 同上 |
| L3 集成/E2E | 完整用户路径，双通道（http + file://） | `tests/e2e.js` | 同上（需先 `npm start`） |
| L4 视觉 | 坐标级版式、动效终态、响应式 | `tests/visual.js` | 同上 |
| L5 手工 | 需真人收码 / 跨账号 / 真机 | 本文 §M 清单 | — |

**通过门槛（CI 定义）**：L1+L2+L3+L4 全绿，且「零 JS 异常」断言不得被过滤；
任何 P0 用例失败即阻断发布。
