# 🧭 Playable Novel 优化提升清单

> 基于 GitHub 开源生态（SillyTavern / KoboldCPP / Narratium.ai / The Endless Tale）与 Reddit / App Store 用户调研（r/CharacterAIrunaways 2026 年度调查、OOC 评论区、r/SillyTavernAI）整理。
> 原则：**拒绝功能膨胀，聚焦互动叙事三大支柱——文笔质量、长期记忆、人设一致性。**

---

## 一、调研核心发现

### 1.1 竞品格局（GitHub）

| 项目 | 定位 | 可借鉴 | 其问题 |
|------|------|--------|--------|
| **SillyTavern** (30k★) | RP 前端控制室 | World Info 关键词注入、分层摘要扩展、向量存储、Data Bank | 安装配置复杂，新手劝退 |
| **KoboldCPP** (11k★) | 本地推理后端 | 单文件、隐私、免费 | 需 GPU，界面简陋 |
| **Narratium.ai** | 轻量叙事引擎（与我们最接近） | 上下文压缩 + Graph-RAG、React Flow 可视化记忆、兼容 SillyTavern 角色卡 | 生态尚早期 |
| **The Endless Tale** | 目标驱动互动小说 | Objectives 系统、自主角色 AI、动态世界状态（时间流逝/角色离场） | 响应慢（~40s/轮） |
| **WorldOS / Isekai Zero** | OOC 竞品 | 世界级持久记忆、看广告赚额度、创作者分成 | 闭源、内容锁平台 |

**记忆技术方案共识**（SillyTavern 生态 + 中文社区实践）：
- **分层摘要**：最近 N 轮逐字保留，旧对话分层压缩（Summaryception 做到数千轮 < 20k tokens）
- **World Info / Lorebook**：关键词触发注入持久设定，条目**用户可读可改**
- **向量检索（RAG）**：按语义召回旧细节，但与 prompt cache 互斥（二选一）
- 最佳实践公式：**「摘要保主线 + RAG 取细节 + 少量手动规则」**；记忆条目必须带时间/章节字段和可检索实体名

### 1.2 用户痛点数据（Reddit / App Store）

| 痛点 | 证据 | 严重度 |
|------|------|--------|
| **记忆遗忘**（头号公敌） | 63% 用户将记忆列入 top3 需求；OOC 有用户 700+ 输入、三个篇章后 AI 仍遗忘；「AI 擅自修改已发生的事实」 | ⭐⭐⭐ |
| **被迫当编辑** | 社区自发产出大量「教 AI 记忆」攻略：整理长期记忆、补 user note、手动改错误回复 | ⭐⭐⭐ |
| **回复截断/不完整** | OOC 评论区高频抱怨：回复被切断要再花积分继续 | ⭐⭐ |
| **积分墙挫败** | 免费 300 积分/天仅够 2-3 条高档消息；单人月耗 $150+；玩家主动要求「看广告换额度」 | ⭐⭐ |
| **人设漂移/重复输出** | c.ai 换模型后被评 "forgetful, repetitive, out of character"；模型陷入循环 | ⭐⭐ |
| **无法手动干预** | 46% 用户最想要「手动编辑角色消息」能力 | ⭐⭐ |
| **平台锁定** | 用户留在差平台只因「迁移 = 放弃长故事」；导出/迁移是刚需 | ⭐⭐ |
| **功能膨胀** | 54% 用户称永远不会用语音/图像功能，认为是挪用核心体验资源 | ⭐⭐（反向警示） |

### 1.3 我们的结构性优势（竞品没有的）

1. **BYOK + 开源**：天然无积分墙、无内容过滤、无平台锁定、数据隐私 —— 直接命中上表 4 个痛点
2. **用户自有小说**：OOC/WorldOS 只能玩平台内容；我们让读者走进**自己**的书 —— 这是无人占据的生态位
3. **演示模式**：零门槛体验，评委/用户 30 秒上手

## 二、优化清单

### 🔴 P0 — 体验生死线（1-2 周内完成）

#### P0-1 分层记忆系统（Memory Ladder）
- **痛点依据**：记忆是 63% 用户的 top3 需求，OOC 700 轮遗忘是评论区最著名差评
- **方案**（对标 Summaryception + Memory Books）：
  1. **逐字层**：最近 6 轮原文进 prompt
  2. **摘要层**：每累计 6 轮，用一次轻量调用把更早内容压缩为「故事至今」段落（含时间/章节字段），持续滚动更新
  3. **设定层**：世界卡片（已实现）+ 用户可编辑世界书（见 P1-5）
  4. **兜底层**：超长会话时对原著上下文做关键词召回（用户输入与原文句子重叠打分，复用现有 mock 打分逻辑）
- **落点**：`server.js` 新增 `/api/ai/summarize`；`app.js` state 增加 `rollingSummary`，随 `history` 滚动更新；侧边栏展示「记忆体」当前内容

#### P0-2 流式输出（SSE Streaming）
- **痛点依据**：OOC 用户抱怨「回复被切断还要再花钱」；阻塞式请求等待感差
- **方案**：`/api/ai/chat` 改为 SSE 增量推送（OpenAI `stream: true`），前端打字机渲染；用户可随时「停止生成」
- **注意**：流式会破坏 prompt cache 前缀复用，需在设置里提供「流式 / 缓存优先」开关（SillyTavern 文档明确二者互斥）

#### P0-3 消息干预三件套（编辑 / 重写 / 删除回溯）
- **痛点依据**：46% 用户最想要手动编辑能力；用户社区被迫自学「改错误回复」技巧
- **方案**：每条消息 hover 出现操作栏——
  - 用户消息：✏️ 编辑后重发（后续剧情基于新输入重新生成）
  - AI 消息：🔄 重新生成（换 seed/温度微调）、✂️ 删除此条及后续
  - 🕐 时间线：点击任意历史节点回到该状态（localStorage 快照，对标 Narratium 的 React Flow 简化版）

#### P0-4 成本感知面板（BYOK 用户刚需）
- **方案**：侧边栏实时显示本次会话：累计 tokens、估算费用（按各平台公开价）、轮次成本 Top；每轮生成后从 API `usage` 字段回写
- **理由**：BYOK 用户花的是自己的钱，「看得见的消耗」是开源平台对闭源积分墙的信任回应

### 🟡 P1 — 差异化竞争力（2-4 周）

#### P1-5 世界书（Lorebook）系统
- **方案**：世界卡片自动拆分为结构化条目（人物/地点/物品/规则/伏笔），用户可增删改；按关键词触发注入（SillyTavern World Info 机制），带「始终生效 / 关键词触发」两档
- **亮点文案**：「你的原著设定，AI 永远记得——而且你可以亲手改」

#### P1-6 原著一致性守护（Canon Guard）
- **痛点依据**：「AI 擅自改变发生过的事情」是 OOC 记忆类差评的核心
- **方案**：
  1. 每 10 轮生成一份「原著事实清单」（已发生事件/人物状态/持有物品），注入后续 prompt
  2. 生成后轻量校验：新剧情与事实清单冲突时，前端标黄提示「⚠️ 此段可能与原著设定冲突，可重写」
- **这是我们对 OOC 的技术制高点**：我们有原著全文， consistency 校验有 ground truth

#### P1-7 剧情分支与「如果」存档
- **方案**：关键节点自动存档；「另走他路」按钮从任意历史点分裂新时间线；分支树可视化（简化版：可折叠列表 + 节点摘要，不上 React Flow 保持零依赖）

#### P1-8 角色状态面板（游戏化层）
- **方案**（对标 The Endless Tale / WorldOS）：AI 每轮附带输出结构化状态：当前位置 / 在场人物 / 关系变化 / 持有物品 / 未解伏笔；侧边栏常驻展示
- **落点**：扩展现有 JSON 输出协议 `{narration, suggestions, mood, state:{location, present[], relations{}, items[], foreshadowing[]}}`

#### P1-9 场景插画（可选，默认关闭）
- **依据**：OOC 好评第一是「动漫感」，但 54% 用户认为图像是资源挪用——**做成可选配置**：用户填自己的图像 API（OpenRouter 的 flux/sd 端点即可）后开启，每场景一张，不打断阅读流

#### P1-10 导出与分享（反锁定宣言）
- **方案**：一键导出本局为 Markdown（含世界卡片 + 剧情 + 你的每个选择）/ JSON 存档 / 分享链接（压缩编码，无服务端）；README 明示「你的故事永远属于你」

## 三、明确「不做」清单（行业教训）

1. ❌ **语音通话 / 3D 形象** —— 54% 用户永不使用，且挪用核心体验资源
2. ❌ **自建积分/付费墙** —— 我们的立场是 BYOK，任何平台代收费都与定位冲突
3. ❌ **平台级内容过滤** —— 审查责任在用户与模型供应商，我们只提供工具（README 需声明合规边界）
4. ❌ **重插件系统** —— 保持零依赖单文件后端，P1 全部功能内置而非插件化

## 四、执行路线图

```
第 1 周  P0 全家桶：记忆阶梯 + SSE 流式 + 消息干预 + 成本面板
         ↓ 目标：长会话（100+ 轮）不崩、不断、可回改、看得见成本
第 2-3 周 P1 核心件：世界书 + Canon Guard + 分支存档
         ↓ 目标：形成「原著级一致性」技术叙事（参赛答辩记忆点）
第 4 周  P1 体验件：角色状态面板 + 导出分享 + 可选插画
         ↓ 目标：demo 完整度对标 OOC 主流程
第 5 周+ P2 生态件：角色卡导入、EPUB、PWA
```
